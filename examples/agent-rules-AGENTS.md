# AGENTS.md

Instructions for coding agents (Claude Code, Cursor, Codex, Copilot…) working on Tidyteam.
Keep this file current: when a convention changes, change it here.

## Project overview

Tidyteam schedules jobs for cleaning companies: an owner creates jobs, assigns them to crew
members and bills clients. Every company is an **organization** (Better Auth organizations
plugin); users can belong to several, and the active one is on the session.

## Stack

- Next.js 16 (App Router, `src/app`), React 19, TypeScript 5.9 with `strict` and
  `noUncheckedIndexedAccess`
- PostgreSQL via Drizzle ORM 0.45 + postgres.js; migrations with drizzle-kit
- Auth: Better Auth 1.7 with the `organization` plugin (`src/lib/auth.ts`)
- Validation: Zod 4
- Styling: Tailwind CSS 4 + shadcn/ui (`new-york`, neutral, CSS variables); icons from
  `lucide-react`; forms with React Hook Form
- Payments: Stripe · Email: Resend
- Package manager: **pnpm**. Never use npm or yarn, and never commit another lockfile.

## Commands

```bash
pnpm install          # install dependencies
pnpm dev              # dev server on http://localhost:3000 (Turbopack)
pnpm build            # production build (output: "standalone")
pnpm lint             # ESLint
pnpm format           # Prettier (writes files)
pnpm typecheck        # tsc --noEmit
pnpm test --run       # Vitest once; plain `pnpm test` starts watch mode
pnpm test:e2e         # Playwright (e2e/)
pnpm db:generate      # generate a migration from src/lib/db/schema.ts
pnpm db:migrate       # apply migrations to DATABASE_URL
```

## Project structure

- `src/app/` — routes. `(dashboard)/` holds signed-in pages; `api/` holds route handlers
  (`api/auth/[...all]` is Better Auth's handler, `api/webhooks/stripe` is the Stripe webhook).
- `src/server/` — server actions, one file per domain (`jobs.ts`), each starting with
  `"use server"`. Route handlers call these instead of duplicating logic.
- `src/lib/db/schema.ts` — Drizzle schema; `src/lib/db/index.ts` — the `db` client.
  Generated migrations live in `drizzle/`.
- `src/lib/` — server helpers: `auth.ts`, `stripe.ts`, `money.ts`.
- `src/components/` — app components; `src/components/ui/` is generated by shadcn/ui.
- `src/env.ts` — validated environment variables.
- `e2e/` — Playwright tests.

## Conventions

- Import with the `@/` alias (`@/lib/db`), never `../../..`.
- Server components by default. Add `"use client"` only for state, effects or browser APIs,
  and keep client components free of server imports (`@/lib/db`, `@/env`, `@/lib/stripe`).
- Money is stored as integer cents (`priceCents`) and formatted with `formatCents` from
  `@/lib/money`. Never use floats for money: they lose precision.
- Database columns are snake_case in SQL, camelCase in the Drizzle schema
  (`organizationId: text("organization_id")`).
- Add shadcn/ui components with `pnpm dlx shadcn@latest add <name>`; don't hand-edit files in
  `src/components/ui/` except to change tokens.

## Architecture and security rules

1. Every server action and route handler starts the same way as `deleteJob` in
   `src/server/jobs.ts`:
   - get the session with `auth.api.getSession({ headers: await headers() })`;
   - take `session.session.activeOrganizationId` and throw if it is missing;
   - parse the input with a Zod schema before using it.
   Server actions are public HTTP endpoints even if no page links to them.
2. Every query on `jobs` (and any future business table) filters by `organizationId` from the
   session, never from the request body, URL or form data. Updates and deletes combine the id
   and the organization: `and(eq(jobs.id, id), eq(jobs.organizationId, organizationId))`.
3. Secrets stay on the server. Never add a `NEXT_PUBLIC_` variable for anything but public
   config (`NEXT_PUBLIC_APP_URL` is the only one today).
4. Read env vars through `env` from `@/env` (Zod-validated at startup). Add new variables to
   the schema in `src/env.ts` and to `.env.example` with a placeholder value.
   Known exception to fix: `src/lib/stripe.ts` still reads `process.env` directly.
5. Stripe webhooks (`src/app/api/webhooks/stripe/route.ts`): verify with
   `stripe.webhooks.constructEvent` on `await request.text()` (the raw body, never
   `request.json()`), and make handling idempotent by `event.id` before changing data —
   Stripe retries deliveries.
6. There is no rate limiter yet. Don't add public endpoints (sign-up, public forms) without
   asking first; the decision on a rate limiter is pending.
7. No `any` without a comment explaining why. Use `unknown` and parse with Zod at boundaries.

## Database

- Change tables only in `src/lib/db/schema.ts`, then run `pnpm db:generate` and commit the
  generated SQL in `drizzle/`. Never edit files in `drizzle/` by hand.
- Business tables have `id`, `organizationId`, `createdAt`.
- Never run `pnpm db:migrate` against a database other than local development unless asked.

## Testing

- Vitest for unit tests, colocated as `*.test.ts` next to the code (`src/lib/money.test.ts`).
- Playwright for end-to-end tests in `e2e/` (`*.spec.ts`).
- Write the test first for anything touching permissions, organization scoping, billing or
  money calculations.

## Before finishing a task

Run these and fix every failure before saying the task is done (CI runs the same):

```bash
pnpm lint && pnpm typecheck && pnpm test --run
```

Run `pnpm test:e2e` too when you changed a page or a user flow. Report failures with their
output instead of hiding or skipping them.

## Never

- Commit `.env*` files other than `.env.example`, or real secrets anywhere.
- Change billing or Stripe code without a test that covers the change.
- Disable ESLint rules, `@ts-ignore` errors or skip tests to make a check pass.
- Add a dependency without saying why; prefer what is already installed (Zod, React Hook
  Form, Radix via shadcn/ui).
