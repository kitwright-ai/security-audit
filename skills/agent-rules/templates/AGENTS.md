## Architecture and security rules

<!-- Keep what applies, name the project's real helpers, and say why when it isn't obvious. -->

1. Every server action and route handler starts with: authenticate ({{AUTH_HELPER}}), check the
   user may do this ({{PERMISSION_HELPER_OR_ROLE_CHECK}}), validate input with
   {{VALIDATION_LIBRARY}}. Server actions are public HTTP endpoints even if no page links to them.
2. Scope every query on user data by {{userId | organizationId}}, taken from the session, never
   from the request body or URL. {{Supabase: keep RLS enabled on every table; the service role
   key bypasses RLS and is only used in {{FILE}}.}}
3. Secrets live only in server-side environment variables. Never prefix a secret with
   `NEXT_PUBLIC_` (it ships to the browser) and never import server modules from client components.
4. Read env vars only through `{{ENV_MODULE}}`, which validates them at startup. Add new ones there
   and to `.env.example` (placeholder values only).
5. Webhooks ({{PROVIDER}}): verify the signature on the raw body before doing anything, and make
   handling idempotent by event id. {{WEBHOOK_PATH}}
6. Rate-limit public endpoints (sign-in, sign-up, public forms, webhooks) with {{RATE_LIMITER}}.
7. No `any` without a comment explaining why; prefer `unknown` + validation at boundaries.
